Architecture

Each component runs as an independent container connected by Apache ActiveMQ Artemis (AMQP 1.0). This decoupled design means you can run any subset of components — from a single acquisition node to a full multi-site pipeline — without modifying any code. All inter-component communication is JSON over AMQP topics; no component calls another directly.

Resource Manager ↗

C++20

The central hardware broker. Every application that needs IQ samples submits a task request; the Resource Manager schedules it, allocates a UDP port, and streams IQ to the requester. No application accesses the SDR hardware directly.

Scheduling features

Priority preemption

Three-tier rank: Acquisition (1) < Classification (2) < Direction Finding (3). Higher-rank tasks preempt lower-rank and release the SDR on completion. Prevents monopolisation.

Shared-LO fan-out

Two tasks at the same centre frequency share a single hardware channel via sub-band decomposition. A second subscriber pays zero retune cost and gets IQ immediately.

Independent-LO

On multi-RX devices (USRP B210, LimeSDR), tasks at different frequencies run truly simultaneously on separate RF chains — full bandwidth for each task.

Combined-window

A second task within the device's instantaneous bandwidth triggers a retune to a wider centre frequency covering both. Neither task loses samples during the transition.

AcquisitionApp ↗

C++2064 tests ✓

Continuous spectrum scanner. Submits frequency-sweep tasks to the Resource Manager, receives CF32 IQ over UDP, runs a four-stage signal detection pipeline, and publishes every detection to rf.detections. Detections also persist to PostgreSQL for historical querying.

Detection pipeline

📊
Welch averaging

50%-overlapping Blackman-Harris windowed FFT frames averaged linearly. Reduces noise variance by ~18 dB vs a single-shot FFT, enabling detection of signals just above the noise floor.

→
🎯
CA-CFAR

Cell-averaging CFAR with O(N) prefix-sum implementation. 8 guard + 32 reference cells per side. Threshold adapts to local noise density — stable in mixed signal environments.

→
🔁
Persistence filter

Signal must appear in ≥2 consecutive sweeps before emitting. Strong signals (PAPR ≥15 dB) bypass the filter and emit immediately on first detection.

→
📍
Sub-bin interpolation

3-point parabolic fit on the FFT peak bin. Achieves ~1–2 kHz centre-frequency accuracy regardless of FFT bin width.

P25 voice channel following

When DemodApp publishes a P25 channel grant to rf.p25.grants, AcquisitionApp's P25GrantConsumer submits a priority NARROWBAND task at the granted voice channel frequency. The captured IQ is published to rf.detections tagged with the talk-group ID (e.g. scanner_id=scanner-0-tg1001), allowing downstream components to process it as a labelled signal.

Sweep throughput~7.6 s / 920 MHz at 20 MSPS with 4096-point FFT and 50% overlap (no analysis pause)
Minimum detectable signal−98 dBm with PAPR ≥ 3 dB reliably detected in live hardware tests at 400–2000 MHz
Frequency accuracy±1–2 kHz with sub-bin parabolic interpolation at typical sample rates
False alarm controlCFAR threshold_db tunable per deployment + 2-sweep persistence confirmation

AnalysisApp — Signal Classification ↗

C++2033 tests ✓

Automatic modulation recognition (AMR) service. Classifies every detected signal into one of 36 modulation and protocol classes without any manual tuning. Uses a two-path ONNX pipeline to balance speed and accuracy.

Fast path — ~5 ms

A 36-class RadioResNet runs directly on the 1024-sample IQ snapshot embedded in every RF_DETECTION message. No SDR re-acquisition is needed. Fires when classifier confidence ≥ 0.75.

The model was trained on 922k synthetic samples with realistic hardware impairments: IQ imbalance (±0.5 dB), DC offset, phase noise, AWGN (−10 to +30 dB SNR), and multipath (1–3 taps).

Slow path — ~80 ms

Triggered when fast-path confidence < 0.75. Requests 65k fresh samples via a NARROWBAND task, then computes:

  • 4th-order cumulants (C42, C40) for modulation order
  • OFDM cyclic prefix ratio
  • FM peak deviation
  • Linear chirp rate (LFM/CSS)
  • PAPR and spectral flatness

Features feed a rule engine and ONNX inference in parallel. The higher-confidence result is published.

DemodApp — Demodulation ↗

C++20CI ✓

Demodulates classified RF signals into decoded content — audio PCM, bit streams, or text. Subscribes to rf.analysis (AnalysisApp classifications), fetches IQ for signals above the confidence threshold, and publishes decoded output to rf.demod.

All physical-layer demodulation uses liquid-dsp: FM frequency discriminator, RRC-matched symbol synchroniser, Gaussian filter (GMSK), Costas-loop carrier recovery (PSK/QAM), and 4-level slicer (4FSK). A shared IDemod interface means adding a protocol requires only one new class.

P25 control channel decoder

The P25Monitor continuously decodes the P25 Phase 1 control channel independently of voice traffic. It C4FM-demodulates (4FSK, 4800 sym/s, ±600/±1800 Hz) the control channel IQ, parses Trunking System Blocks (TSBKs), and extracts:

  • IDEN_UP — channel identifier → frequency mapping (band plan)
  • RFSS_STATUS_BCAST — WACN, System ID, site identity
  • GRP_V_CH_GRANT — group voice channel grant (TG → voice freq)
  • IND_V_CH_GRANT — individual/unit-to-unit voice channel grant

Grants matching the configured talk-group whitelist are published to rf.p25.grants for AcquisitionApp to act on.

DfApp — Direction Finding ↗

C++20CI ✓

Estimates the bearing (direction of arrival) of detected RF signals using the MUSIC algorithm (MUltiple SIgnal Classification). Operates on IQ snapshots from multiple receivers that share a common oscillator reference — phase differences between antenna elements are then purely geometric.

Algorithm

  1. Collect IQ snapshots from M antenna elements (same signal, different positions)
  2. Build the M×N complex sample matrix X (M antennas, N samples each)
  3. Form the spatial covariance matrix R = X Xᴴ / N
  4. Eigendecompose R → signal subspace Eₛ and noise subspace Eₙ
  5. Sweep azimuth θ at 0.5° resolution: P(θ) = 1 / ‖ Eₙᴴ a(θ) ‖²
  6. Return the azimuth of the global spectral peak with its prominence as confidence
PMUSIC(θ) = 1 / ‖ ENH a(θ) ‖²

Phase coherence

All receivers must share a common LO reference. Options: GPS-disciplined oscillator (best), hardwired reference signal, or a shared timing pulse. Without coherence, phase offsets between receivers are random and bearing estimation fails. The aggregation window (default 5 s) controls how long snapshots are held waiting for all elements to report.

Measured bearing accuracy

5-element UCA, SNR 25 dB< 2° RMS error — verified at 0° / 90° / 135° / 180° / 270° azimuths in unit tests
5-element UCA, SNR 10 dB< 3° — still convergent at moderate noise; confidence score drops proportionally
2-element minimum, SNR 25 dB< 5° — usable but with 180° ambiguity (left/right); 3+ elements recommended
UHF (433 MHz)< 2° — steering vector correctly recomputed for different wavelength
Confidence score0–1 derived from MUSIC peak-to-mean prominence; published alongside azimuth in DF_RESULT
Sweep resolution0.5° default (configurable). Finer resolution increases CPU linearly with no algorithm change.

SpeechApp — Voice Transcription ↗

C++20

Passive subscriber to rf.demod audio. Two-stage pipeline: an energy VAD gates Whisper inference (skipping silence and noise in <1 ms), then whisper.cpp transcribes detected speech. No Python, no PyTorch at runtime — pure C++ GGML inference. All transcriptions are stored in SQLite and a rolling daily text log.

EnergyVad — <1 ms

RMS energy gate with configurable dBFS threshold. Rejects silence, broadband noise, DTMF, tones, and FSK/digital bursts that wouldn't contain intelligible speech. Only signals with voice-band energy pass to Whisper.

Breakdown by SNR: VAD correctly detects speech at p=1.000 even at SNR 5 dB with 50 Hz AC hum and multipath dropouts.

whisper.cpp

GGML-quantised Whisper running as a native C++ library. Supports CPU (int8 quantisation) and CUDA (float16). Automatic language detection. Segments aligned to word boundaries. Runs on the same host as the rest of the stack with no additional services.

Input is automatically resampled from any sample rate to 16 kHz (Whisper's native rate) using linear interpolation.

P25 / APCO-25 Trunked System Monitoring

The stack implements an end-to-end Phase 1 P25 pipeline: control channel decoding, talk-group filtering, automatic voice channel following, and persistent grant logging. The entire pipeline runs without human intervention once configured.

How it works

1
Detect

AcquisitionApp finds C4FM energy at the control channel frequency — identified by near-zero PAPR and ~12.5 kHz flat spectral footprint

→
2
Decode

P25Monitor in DemodApp fetches IQ at the control frequency. C4FM demodulator (4FSK 4800 sym/s, ±600/±1800 Hz) produces dibits. TSBK parser extracts grants.

→
3
Filter

Configurable talk-group whitelist. Grants for whitelisted TGs (or all TGs if whitelist is empty) are published to rf.p25.grants

→
4
Follow

AcquisitionApp P25GrantConsumer submits a NARROWBAND task at the voice channel frequency. Captured IQ is tagged with the talk-group ID.

→
5
Transcribe

DemodApp demodulates voice (FM path for C4FM). SpeechApp VAD + Whisper transcribes. Stored in transcripts.db.

SdrSdk ↗

C++20

C++ client library for writing SDR applications without touching AMQP internals, raw sockets, or task scheduling. Provides a clean API for task submission, IQ streaming, and spectrum analysis. Physical quantities use the Au units library — frequency, bandwidth, and duration parameters are type-checked at compile time.

#include <sdrsdk/sdrsdk.hpp>
#include <au/units/hertz.hh>
#include <au/units/seconds.hh>

sdr::SdrClient client("amqp://localhost:5672");
client.connect();

// Submit a 3-second NARROWBAND capture at 462.5 MHz
auto resp = client.narrowband(
    au::hertz(462.5e6),   // centre frequency
    au::hertz(12.5e3),    // bandwidth
    au::hertz(48e3),      // sample rate
    au::seconds(3.0));    // duration

// Receive IQ via UDP
sdr::IqStream stream(resp.streams[0].udp_port);
auto iq = stream.collect_complex_for(au::seconds(3.0));
client.stop(resp.task_id);

// Analyse
sdr::Spectrum spec(4096);
auto signals = spec.analyse(iq, au::hertz(462.5e6), au::hertz(48e3));
for (auto& s : signals)
    std::cout << s.freq.in(au::mega(au::hertz)) << " MHz  " << s.type << "\n";

All components consume this as a sibling-directory dependency via CMake add_subdirectory(). Physical quantities (frequency, sample rate, duration) use Au units to prevent unit mismatches at compile time.
