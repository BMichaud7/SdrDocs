SdrTaskApi ↗

C++20

Shared message types and serialisation layer used by every component in the stack. Defines TaskRequest, TaskRecord, AssignedStream, and the JSON codec.

📦 Static library 🔗 Used by all other C++ repos via add_subdirectory()

Key types

  • TaskRequest — SCAN / NARROWBAND / WIDEBAND / TRIGGERED task
  • TaskRecord — lifecycle tracking (PENDING → RUNNING → COMPLETED)
  • MessageCodec — nlohmann/json ↔ struct serialisation

SdrSdk ↗

C++20

High-level C++ SDK wrapping the AMQP task API and UDP IQ streaming. Write SDR applications without touching proton internals or raw sockets.

SdrResourceManager ↗

C++20

The broker between software components and physical SDR hardware. Manages task scheduling, preemption by rank, and UDP IQ streaming to multiple consumers simultaneously.

Trunked scheduling
Rank-based preemption (1=Acq < 2=Analysis < 3=DF)
Shared LO
Two tasks at the same frequency share one hardware channel
IndepLo
Two tasks at different frequencies run simultaneously
Fan-out
One IQ stream → multiple subscribers via sub-band decomposition

AcquisitionApp ↗

C++20 64 tests

Continuous spectrum scanner. Submits frequency-sweep tasks, receives CF32 IQ over UDP, runs Welch FFT + CA-CFAR detection, and publishes detections to rf.detections. Includes a P25 grant consumer that retunes to voice channels on channel grants.

Detection pipeline

  1. Welch averaging — reduces noise variance by ~18 dB vs single FFT
  2. CA-CFAR — O(N) prefix-sum, adapts to local noise floor
  3. Persistence filter — requires ≥2 consecutive detections; strong signals bypass
  4. Sub-bin interpolation — 3-point parabola, ~1-2 kHz accuracy

P25 voice following

When DemodApp publishes a P25 channel grant on rf.p25.grants, AcquisitionApp tunes to the voice channel, captures IQ, and publishes detections tagged with the talk group ID.

AnalysisApp ↗

C++20 33 tests

RF signal auto-identification service. Classifies every detection using a two-path approach: fast ONNX inference on the embedded IQ snapshot, then slow feature extraction + rule engine for edge cases.

Fast path (~5 ms)

28-class ResNet runs on the 1024-sample IQ snapshot embedded in RF_DETECTION. No SDR re-acquisition needed.

Slow path (~80 ms)

Requests 65k samples via NARROWBAND task. Extracts cumulants, OFDM CP, FM deviation, chirp rate. Feeds into rule engine + ONNX.

ML model

36-class RadioResNet (C4FM, DMR, NXDN, D-STAR, TETRA, AIS, POCSAG, ACARS + original 28 classes). Trained on 922k synthetic samples with ±0.3% post-AFC frequency offset and hardware impairments.

P25 control channel decoder

P25Monitor continuously decodes the trunked control channel: extracts channel grants from TSBKs, filters by talk-group whitelist, and publishes grants to rf.p25.grants.

DfApp ↗

C++20

Direction finding using the MUSIC algorithm (Multiple Signal Classification). Aggregates IQ snapshots from multiple PlutoSDRs sharing a common LO reference, computes the covariance matrix, and extracts bearing via eigendecomposition.

azimuth = argmaxθ { 1 / (a(θ)ᴴ EN ENᴴ a(θ)) }

Requires ≥ 2 antennas. 5-element UCA gives ±2° accuracy at SNR > 10 dB. Results published to rf.df_results.

SpeechApp ↗

C++20 (core)

Passive RF speech detection and transcription. Subscribes to rf.demod, applies energy-based VAD, then transcribes detected speech with whisper.cpp. Writes to a rolling SQLite database and daily text logs.

VAD — EnergyVad

RMS energy gate (<1 ms). Skips Whisper for silence, noise bursts, and DTMF. Threshold configurable via XML.

STT — whisper.cpp

GGML Whisper (base.en / small / medium). CPU + CUDA. Auto-detects language. Segments aligned to word boundaries.

┌─ SPEECH  482.663 MHz  P25  (lang=en p=0.94)
│  Units 4 and 7 respond to the intersection of Main and Elm.
└─

SdrScanner ↗

C++20 / Qt6

Cross-platform desktop GUI for real-time spectrum monitoring. Displays Welch spectrum, signal detections, and classification results. Connects to the AMQP bus to subscribe to rf.detections.

Builds on Linux (Qt6 apt) and Windows (Qt6 via vcpkg). CI produces a Windows .zip artifact.

SdrIdentity ↗

Shell / Alpine

Boot-time identity assignment for Tezuka/PlutoSDR fleet devices. All nodes boot with the same default hostname (pluto). This assigns each device a unique hostname by matching its MAC address against config.xml, then updates mDNS so the device is reachable as sdr-N.local.

Signal Classification (ML)

AnalysisApp uses a 36-class RadioResNet trained on 922k synthetic samples covering all supported modulation types and protocols.

36Classes
837kParameters
922kTraining samples
0.3%SR freq offset (post-AFC)

Training data

  • synth_v3_protocols.npz — 810k samples, all 36 classes, ±0.3% SR freq offset + IQ impairments (replaces old ±2% which destroyed constellation structure)
  • qam_heavy.npz — 112k samples, QAM classes only, post-AFC impairments + multipath (harder data)

Two-path architecture

RF_DETECTION → [IQ snapshot embedded]
                    ↓
              OnnxClassifier (fast, ~5ms)
              confidence ≥ 0.75 → publish
              confidence  < 0.75 → slow path
                    ↓
              IqFetcher (65k samples)
              FeatureExtractor → rule engine
              + ONNX inference → publish
