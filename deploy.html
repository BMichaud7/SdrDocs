Docker Compose Setup

1

Clone all repositories

All repos must be siblings — the build system uses relative paths (../SdrSdk, ../SdrTaskApi).

mkdir openrfstack && cd openrfstack
for repo in SdrSdk SdrTaskApi SdrResourceManager AcquisitionApp \
            DemodApp AnalysisApp SpeechApp SdrScripts; do
  git clone --branch main/1.0 https://github.com/OpenRFStack/$repo.git
done
2

Configure environment variables

# .env — place next to docker-compose.yml
AMQP_HOST=artemis
AMQP_PORT=5672
AMQP_USER=openrf
AMQP_PASS=changeme
POSTGRES_USER=openrf
POSTGRES_PASSWORD=changeme
POSTGRES_DB=openrfstack
MODEL_PATH=/models/amr_cnn_v1_47class.onnx
3

docker-compose.yml

services:

  artemis:
    image: apache/activemq-artemis:2.31.2
    environment:
      ARTEMIS_USER: ${AMQP_USER}
      ARTEMIS_PASSWORD: ${AMQP_PASS}
    ports: ["5672:5672", "8161:8161"]

  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes: [pg_data:/var/lib/postgresql/data]

  sdr_resource_manager:
    build: ./SdrResourceManager
    devices: ["/dev/bus/usb:/dev/bus/usb"]   # USB SDR passthrough
    privileged: true
    depends_on: [artemis]

  acquisition:
    build: ./AcquisitionApp
    depends_on: [artemis, sdr_resource_manager]
    volumes: [./AcquisitionApp/config:/config:ro]

  demod:
    build: ./DemodApp
    depends_on: [artemis]

  analysis:
    build: ./AnalysisApp
    deploy:
      resources:
        reservations:
          devices: [{driver: nvidia, count: 1, capabilities: [gpu]}]
    volumes:
      - ./models:/models:ro
      - ./AnalysisApp/config:/config:ro
    depends_on: [artemis]

  speech:
    build: ./SpeechApp
    depends_on: [artemis]

volumes:
  pg_data:
4

Initialize the database schema

docker compose up -d postgres
docker compose exec postgres psql -U openrf openrfstack \
  -f /docker-entrypoint-initdb.d/init.sql
# Or mount AcquisitionApp/schema/init.sql as initdb script
5

Start the full stack

docker compose up -d
docker compose logs -f acquisition demod analysis

# Artemis management UI: http://localhost:8161 (admin/changeme)
# PostgreSQL:            localhost:5432

This section assumes k3s on a single node with GPU operator. For multi-node see the SdrScripts repo's k8s/ directory.

kind: StatefulSet

  name: postgres
spec:
  serviceName: postgres
  replicas: 1
  volumeClaimTemplates:
  - metadata: {name: pg-data}
    spec:
      accessModes: [ReadWriteOnce]
      resources: {requests: {storage: 20Gi}}
  template:
    spec:
      containers:
      - name: postgres
        image: postgres:15-alpine
        env:
        - {name: POSTGRES_PASSWORD, valueFrom: {secretKeyRef: {name: pg-secret, key: password}}}
        volumeMounts:
        - {name: pg-data, mountPath: /var/lib/postgresql/data}
# AnalysisApp with GPU request
resources:
  limits:
    nvidia.com/gpu: 1
  requests:
    nvidia.com/gpu: 1

# Mount ONNX model from ConfigMap or PVC
volumeMounts:
- name: models
  mountPath: /models
  readOnly: true

# AcquisitionApp — needs SDR USB device access
# See USB passthrough tab for hostPath volume approach
# USB SDR passthrough via hostPath (single-node only)
volumes:
- name: usb-bus
  hostPath:
    path: /dev/bus/usb
    type: Directory

volumeMounts:
- name: usb-bus
  mountPath: /dev/bus/usb

# Required for SoapySDR USB access
securityContext:
  privileged: true

# udev rule on the host (run once):
echo 'SUBSYSTEM=="usb", ATTRS{idVendor}=="0bda", MODE="0666"' \
  | sudo tee /etc/udev/rules.d/99-rtlsdr.rules
sudo udevadm control --reload-rules

Configuration Reference

Each app reads its config from an XML file. Mount the config directory as a read-only volume. The most important knobs for initial setup: 
<!-- AcquisitionApp/config/scanner.xml — key fields -->
<scanner>
  <amqp host="artemis" port="5672" user="openrf" password="changeme"/>
  <sdr  driver="rtlsdr" serial="00000001" sample_rate="2400000"/>
  <scan center_hz="100000000" span_hz="2000000" dwell_ms="100"/>

  <threat>
    <gps_jamming    enabled="true"  ema_alpha="0.05" threshold_db="6.0"/>
    <gps_spoofing   enabled="true"/>
    <adsb_physics   enabled="true"/>
    <ais_anomaly    enabled="true"/>
    <eas_spoof      enabled="true"/>
    <p25_rogue_site enabled="true"/>
    <p25_retune     enabled="true"/>
  </threat>
</scanner>

<!-- AnalysisApp/config/analysis.xml -->
<analysis>
  <amqp host="artemis" port="5672"/>
  <model path="/models/amr_cnn_v1_47class.onnx"
         classes="/models/amr_cnn_v1_47class_classes.json"
         device="cuda"/>
  <inference batch_size="64" confidence_threshold="0.65"/>
</analysis>

Common Issues

!

SoapySDR device not found in container

The container needs access to /dev/bus/usb and the udev rules must run on the host before the container starts. Verify with:

docker run --rm --privileged -v /dev/bus/usb:/dev/bus/usb \
  openrfstack/sdr_resource_manager SoapySDRUtil --find
!

AMQP connection refused at startup

Apps retry on connection failure, but Artemis can take 10–15 s to be ready. Add a healthcheck or use depends_on: condition: service_healthy in Compose. Artemis health endpoint: http://artemis:8161/console/jolokia/read/org.apache.activemq.artemis:broker=*/Started

!

AnalysisApp: CUDA OOM

Reduce batch_size in analysis.xml. The v1 model (47-class, 128ch) needs ~62 MB VRAM. With batch_size=256 and other processes sharing the GPU, 4 GB cards may OOM. Reduce to 64 or 32:

<inference batch_size="32" confidence_threshold="0.65"/>
!

PlutoSDR: sample drops at high rates

PlutoSDR USB 2.0 limits sustained throughput to ~5 MS/s. At 61.44 MS/s the device overflows. Set sample_rate ≤ 4000000 in scanner.xml. Use a USB 3.0 hub — PlutoSDR still connects via USB 2.0 but avoids shared bandwidth with other USB 3.0 devices that can cause bus contention.

!

pqxx demangle_type_name linker error

Occurs when libpqxx 7.x is paired with std::optional<T> in the same translation unit. The AlertStore uses a pimpl pattern and manually-built SQL strings to avoid this — do not include <pqxx/pqxx> in any header that is also included by a TU that includes <nlohmann/json.hpp>.
